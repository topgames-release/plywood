## 开发环境搭建

要开始为Plywood项目贡献代码，需要正确设置开发环境。本项目基于Node.js平台，需要安装特定版本的Node.js和npm包管理器。

首先，确保系统中安装了Node.js。根据package.json文件中的依赖关系，建议使用与项目兼容的Node.js版本。安装Node.js后，通过npm安装项目所需的所有依赖包：

```bash
npm install
```

此命令将读取package.json文件并安装所有列出的依赖项，包括开发依赖项，如Mocha测试框架、Chai断言库、TypeScript编译器等。安装完成后，开发环境即已准备就绪。

## 构建与编译

Plywood项目使用TypeScript编写，因此需要将TypeScript源代码编译为JavaScript。项目提供了专门的构建脚本来进行编译。

主要的构建命令是：

```bash
npm run compile
```

此命令会执行项目根目录下的`compile`脚本，该脚本负责调用TypeScript编译器并根据tsconfig.json中的配置进行编译。编译后的JavaScript文件将输出到`build`目录中。

此外，项目还提供了直接调用TypeScript编译器的脚本：

```bash
./compile-tsc
```

此脚本直接调用tsc命令，使用项目配置进行编译。开发者可以根据需要选择使用npm脚本或直接运行编译脚本。

## 测试策略

Plywood项目采用全面的测试策略，确保代码质量和功能正确性。测试分为多个类别，位于不同的测试目录中。

运行所有测试的命令是：

```bash
npm test
```

此命令会执行pretest脚本（编译代码）然后运行test脚本，执行所有单元测试。

项目中的测试分为以下几类：

1. **功能测试**: 位于`test/functional/`目录，测试与实际数据源（如Druid、MySQL）的集成功能。
2. **表达式测试**: 位于`test/expression/`目录，测试各种表达式的解析、简化和计算。
3. **数据类型测试**: 位于`test/datatypes/`目录，测试各种数据类型的处理。
4. **外部系统测试**: 位于`test/external/`目录，测试与外部数据源的交互。

要运行特定的测试文件，可以使用Mocha直接调用：

```bash
mocha test/external/druidExternal.mocha.js
```

这将只运行Druid外部系统相关的测试。对于功能测试，可以运行：

```bash
mocha test/functional/druidFunctional.mocha.js
```

## TypeScript配置

项目的TypeScript配置定义在tsconfig.json文件中，该配置确保了代码的类型安全和兼容性。

主要配置选项包括：

- `target`: 编译目标为ES5，确保在各种环境中兼容
- `module`: 使用ES6模块系统
- `rootDir`: 源代码根目录为src
- `outDir`: 编译输出目录为build
- `strictNullChecks`: 关闭严格空值检查
- `declaration`: 生成类型声明文件

这些配置确保了TypeScript代码能够正确编译为JavaScript，并生成相应的类型定义文件，供其他TypeScript项目使用。

```json
{
  "compilerOptions": {
    "target": "es5",
    "module": "es6",
    "rootDir": "src",
    "outDir": "build",
    "strictNullChecks": false,
    "declaration": true
  },
  "include": [
    "typings/private.d.ts",
    "src/**/*.ts"
  ]
}
```

## 代码风格规范

代码风格由tslint.json文件定义，确保代码的一致性和可读性。

主要的代码风格规则包括：

- 缩进使用2个空格
- 行长度限制为200个字符
- 语句对齐
- 成员排序：静态成员在前，实例成员在后
- 分号必须
- 尾随逗号禁止

这些规则通过TSLint工具自动检查，开发者在提交代码前应确保代码符合这些规范。可以使用TSLint命令行工具检查代码风格：

```bash
tslint 'src/**/*.ts'
```

## 功能扩展指南

对于希望扩展Plywood功能的贡献者，项目提供了清晰的扩展指南。

### 添加新的表达式

要添加新的表达式，可以参考dev-docs/new-expression-checklist.md文件中的检查清单。主要步骤包括：

1. 在`src/expressions/`目录下创建新的表达式文件，如`fooBarExpression.ts`
2. 实现`FooBarExpression`类，设置操作类型为`"fooBar"`
3. 在`baseExpression.ts`中添加相应的接口和方法
4. 在`baseExpression.ts`中添加创建此表达式的公共方法
5. 在文档中添加相应的说明
6. 添加相应的测试

### 添加新的数据源

要支持新的数据源，需要在`src/external/`目录下创建相应的外部系统实现，如`mySqlExternal.ts`。需要实现与该数据源的查询构建和结果处理逻辑。

## 代码组织建议

Plywood项目的代码组织遵循清晰的模块化结构，建议新功能的添加遵循现有模式。

### 源代码结构

- `src/datatypes/`: 数据类型定义
- `src/dialect/`: 不同数据库方言的实现
- `src/executor/`: 执行器实现
- `src/expressions/`: 表达式系统
- `src/external/`: 外部数据源接口
- `src/helper/`: 辅助工具

### 测试结构

- `test/datatypes/`: 数据类型测试
- `test/expression/`: 表达式测试
- `test/external/`: 外部系统测试
- `test/functional/`: 功能集成测试
- `test/helper/`: 辅助工具测试
- `test/overall/`: 整体测试

新功能的测试应放在相应的测试目录中，保持测试组织的一致性。
