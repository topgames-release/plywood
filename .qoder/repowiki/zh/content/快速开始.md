## 环境准备

在开始集成 Plywood 之前，请确保您的开发环境已正确配置。Plywood 支持 Node.js 和浏览器环境，因此您需要一个兼容的 JavaScript 运行时。对于 Node.js 用户，建议使用版本 12 或更高版本以确保最佳兼容性。对于浏览器环境，Plywood 可以通过标准的 `<script>` 标签引入，或通过现代前端构建工具（如 Webpack 或 Vite）进行模块化加载。确保您的项目已初始化为 npm 项目（即包含 `package.json` 文件），这将使依赖管理更加简便。

## 安装与引入

要将 Plywood 集成到您的项目中，首先需要通过 npm 安装该库。在您的项目根目录下打开终端并执行以下命令：

```bash
npm install plywood
```

此命令将从 npm 仓库下载 Plywood 及其所有依赖项，并将其添加到您的 `package.json` 文件的依赖列表中。安装完成后，您可以在代码中引入 Plywood。在 Node.js 环境中，使用 `require` 语句：

```javascript
const plywood = require('plywood');
```

在浏览器环境中，您可以通过 `<script>` 标签直接引入，Plywood 将作为全局变量 `plywood` 可用：

```html
<script src="node_modules/plywood/build/plywood.js"></script>
```

## 基础代码结构

一个完整的 Plywood 查询由几个核心部分组成：数据源、过滤条件、分组（split）和聚合（apply）。以下是一个演示如何创建基本数据查询表达式的完整代码示例。该示例假设您已配置好一个 Druid 数据源，并且您的数据集中包含 `__time`（时间戳）、`action_type`（动作类型）和 `isInstall`（是否安装）等字段。

```javascript
// 1. 引入 Plywood
const { Expression, DruidExternal } = require('plywood');

// 2. 创建数据源实例
const dataSource = new DruidExternal({
  engine: 'druid',
  source: 'your_data_source_name',
  timeAttribute: '__time',
  attributes: [
    { name: '__time', type: 'TIME' },
    { name: 'action_type', type: 'STRING' },
    { name: 'isInstall', type: 'NUMBER' }
  ]
});

// 3. 构建查询表达式
const queryExpression = Expression._
  .apply('filtered_data', Expression._.filter(Expression._.is('INSTALL', '$action_type')))
  .apply('total_installs', '$filtered_data.sum($isInstall)');
```

此代码首先创建了一个指向 Druid 数据源的 `DruidExternal` 实例，然后构建了一个表达式，该表达式先过滤出 `action_type` 为 `INSTALL` 的记录，再计算这些记录中 `isInstall` 字段的总和。

## 执行计算与结果

一旦构建好查询表达式，就可以使用 `compute()` 方法来执行计算。该方法需要一个上下文对象，该对象将数据源名称映射到实际的数据源实例。执行后，它返回一个 Promise，解析为包含查询结果的 Dataset 对象。

```javascript
// 4. 准备执行上下文
const context = {
  your_data_source_name: dataSource
};

// 5. 执行计算
queryExpression.compute(context)
  .then(result => {
    console.log('查询结果:', result);
    // 预期输出：一个包含单行数据的 Dataset，其中包含 total_installs 的值
  })
  .catch(error => {
    console.error('查询执行失败:', error);
  });
```

预期输出将是一个 Plywood Dataset 对象，其数据部分包含一行，该行有一个名为 `total_installs` 的字段，其值是所有符合条件的 `isInstall` 字段的总和。这个结果可以直接用于数据可视化或进一步的分析。

## compute() 方法详解

`compute()` 方法是 Plywood 执行查询的核心。它接受两个参数：`context` 和 `options`。`context` 是一个对象，用于将表达式中的数据源名称映射到具体的 `External` 实例（如 `DruidExternal`）。`options` 是一个可选的配置对象，其中可以包含 `customOptions` 参数，用于传递特定于执行环境的自定义配置。

`customOptions` 是一个灵活的参数，允许您向查询执行过程注入额外的指令。例如，它可以用来控制查询超时、设置最大查询次数，或启用特定的优化功能。在 Plywood 中，`customOptions` 的结构是开放的，不同的执行器（executor）可以解释其中的不同字段。例如，`DruidExternal` 可能会检查 `customOptions` 中的 `timeout` 字段来设置查询超时。

## 启用 subtotalsSpec 优化

为了显著提升多维度分析的查询性能，Plywood 提供了 `subtotalsSpec` 优化功能。此功能通过将多个独立的查询合并为一个包含 `subtotalsSpec` 的单一 `groupBy` 查询，从而减少网络往返次数和 Druid 集群的负载。要启用此优化，您需要在 `compute()` 方法的 `options` 参数中设置 `customOptions.useSubtotalsSpec` 为 `true`。

```javascript
// 在 compute() 调用中启用优化
queryExpression.compute(context, {
  customOptions: {
    useSubtotalsSpec: true
  }
})
.then(result => {
  console.log('优化后的查询结果:', result);
})
.catch(error => {
  console.error('优化查询失败:', error);
});
```

当 `useSubtotalsSpec` 被启用时，Plywood 会自动检测查询是否适合优化（例如，是否包含多个 split 操作）。如果条件满足，它将使用 `simulateQueryPlan` 来生成查询计划，然后调用 `_mergeQueriesWithSubtotalsSpec` 将多个查询合并，并最终通过 `_executeSubtotalsQuery` 执行合并后的查询。此优化可以将查询次数从 N+1 次减少到 1 次，性能提升可达 60-90%。

```mermaid

C --> D[调用 simulateQueryPlan]

E --> F[调用 _executeSubtotalsQuery]
F --> G[执行合并的查询]
G --> H[返回结果]
B --> |否| I[调用 _computeResolved]
I --> J[执行常规查询]
J --> H
```

## 故障排除

如果您的查询未能按预期工作，请检查以下常见问题。首先，确保 `DruidExternal` 实例已正确配置，特别是 `requester` 属性，因为它是执行 HTTP 请求所必需的。其次，验证 `context` 对象中的数据源名称与表达式中使用的名称完全匹配。如果启用了 `subtotalsSpec` 优化但未生效，请确认您的 Druid 集群版本为 0.17.0 或更高，因为 `subtotalsSpec` 是一个较新的特性。此外，检查 `customOptions` 是否正确传递，并且 `useSubtotalsSpec` 设置为 `true`。最后，查看控制台日志以获取详细的错误信息，这些信息通常能指出问题的根本原因。
