## 简介
本文档详细阐述了Plywood表达式到Druid后聚合结构的转换机制。重点分析了`expressionToPostAggregation`方法如何将Plywood表达式转换为Druid兼容的后聚合格式，涵盖了各种操作类型的生成规则、字段访问机制和类型推断策略。

## 核心转换机制
`expressionToPostAggregation`方法是Plywood表达式转换为Druid后聚合的核心。该方法首先尝试使用`DruidExpressionBuilder`将表达式转换为Druid表达式格式。如果转换成功，则生成类型为"expression"的后聚合；如果转换失败，则回退到传统的后聚合生成机制。

```mermaid
flowchart TD
Start([开始转换]) --> CheckExpression["检查表达式类型"]
CheckExpression --> ConvertToDruid["尝试转换为Druid表达式"]
ConvertToDruid --> Success{"转换成功?"}
Success --> |是| CreateExpressionPostAgg["创建expression类型后聚合"]
Success --> |否| LegacyConversion["使用传统转换机制"]
LegacyConversion --> RefCheck["检查是否为RefExpression"]
RefCheck --> |是| FieldAccess["创建字段访问后聚合"]
RefCheck --> |否| LiteralCheck["检查是否为LiteralExpression"]
LiteralCheck --> |是| Constant["创建常量后聚合"]
LiteralCheck --> |否| ArithmeticCheck["检查算术操作"]
ArithmeticCheck --> |是| Arithmetic["创建算术后聚合"]
Arithmetic --> End([完成])
```

## 后聚合类型生成规则

### 算术后聚合
算术操作（加减乘除、位运算等）通过"arithmetic"类型的后聚合实现。每种操作对应特定的函数标识符：

```mermaid
classDiagram
class ArithmeticPostAggregation {
+string type : "arithmetic"
+string fn : 函数标识符
+Druid.PostAggregation[] fields : 操作数
}
ArithmeticPostAggregation --> AddOperation : "fn='+'"
ArithmeticPostAggregation --> SubtractOperation : "fn='-'"
ArithmeticPostAggregation --> MultiplyOperation : "fn='*'"
ArithmeticPostAggregation --> DivideOperation : "fn='/'"
ArithmeticPostAggregation --> ModOperation : "fn='%'"
ArithmeticPostAggregation --> BitwiseAndOperation : "fn='&'"
```

### JavaScript后聚合
对于复杂的表达式操作，系统生成JavaScript后聚合。这些聚合包含完整的JavaScript函数定义，支持绝对值、类型转换等高级操作：

```mermaid
sequenceDiagram
participant Expression as Plywood表达式
participant Builder as DruidAggregationBuilder
participant PostAgg as 后聚合
Expression->>Builder : expressionToLegacyPostAggregation()
Builder->>Builder : 分析表达式类型
alt 复杂表达式
Builder->>PostAgg : 生成JavaScript函数
PostAgg->>PostAgg : type : "javascript"
PostAgg->>PostAgg : fieldNames : 字段列表
PostAgg->>PostAgg : function : JS函数体
end
Builder-->>Expression : 返回后聚合结构
```

## 复杂表达式处理策略
对于包含多个操作的复杂表达式，系统采用递归分解策略，将表达式树逐层转换为后聚合结构：

```mermaid
flowchart TD
ComplexExpr[复杂表达式] --> Decompose["分解为子表达式"]
Decompose --> SubExpr1[子表达式1]
Decompose --> SubExpr2[子表达式2]
Decompose --> SubExpr3[子表达式3]
SubExpr1 --> Convert1["转换为后聚合"]
SubExpr2 --> Convert2["转换为后聚合"]
SubExpr3 --> Convert3["转换为后聚合"]
Convert1 --> Combine["组合为最终后聚合"]
Convert2 --> Combine
Convert3 --> Combine
Combine --> FinalPostAgg[最终后聚合结构]
```

## 访问类型确定机制
`getAccessType`方法根据前置聚合的类型确定字段的访问方式。该方法检查聚合类型并返回相应的访问类型：

```mermaid
sequenceDiagram
participant Aggregations as 聚合列表
participant GetAccess as getAccessType
participant Result as 访问类型
GetAccess->>Aggregations : 遍历聚合列表
loop 每个聚合
Aggregations->>GetAccess : 检查聚合名称
alt 名称匹配
GetAccess->>GetAccess : 获取聚合类型
GetAccess->>GetAccess : 处理filtered类型
GetAccess->>GetAccess : 返回对应访问类型
end
end
GetAccess-->>Result : 返回访问类型
alt 未找到
Result->>Result : 默认返回'fieldAccess'
end
```

## 优化策略
系统实现了多种优化策略来提高后聚合的执行效率，包括临时字段生成和表达式简化：

```mermaid
flowchart LR
Original[原始表达式] --> Simplify["表达式简化"]
Simplify --> CheckComplexity["检查复杂度"]
CheckComplexity --> |高复杂度| GenerateTemp["生成临时字段"]
CheckComplexity --> |低复杂度| DirectConvert["直接转换"]
GenerateTemp --> TempField["!F_字段名"]
TempField --> Cache["缓存中间结果"]
Cache --> Final["最终后聚合"]
DirectConvert --> Final
```
