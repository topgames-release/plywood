## 引言
Plywood的聚合功能扩展体系通过混入模式为各类聚合表达式提供统一的语义标识和行为规范。该体系基于TypeScript的混入机制，将聚合语义与具体表达式实现解耦，实现了高度的可扩展性和代码复用性。

## 聚合体系设计原理
聚合体系的核心是`Aggregate`混入类，它定义了所有聚合表达式共有的行为特征。通过混入模式，各类聚合表达式（如求和、计数、平均值等）可以继承这些通用行为，同时保持各自特定的计算逻辑。

```mermaid
classDiagram
class Aggregate {
+operand : Expression
+isAggregate() : boolean
+isNester() : boolean
+fullyDefined() : boolean
}
class SumExpression {
+distribute() : Expression
+_calcChainableUnaryHelper() : PlywoodValue
+_getSQLChainableUnaryHelper() : string
}
class AverageExpression {
+decomposeAverage() : Expression
+_calcChainableUnaryHelper() : PlywoodValue
+_getSQLChainableUnaryHelper() : string
}
class CountExpression {
+calc() : PlywoodValue
+_getSQLChainableUnaryHelper() : string
}
Aggregate <|-- SumExpression
Aggregate <|-- AverageExpression
Aggregate <|-- CountExpression
```

## 核心方法分析
### isAggregate() 方法
`isAggregate()`方法是聚合表达式类型系统的核心标识，它返回`true`以表明该表达式具有聚合语义。这个方法被所有继承`Aggregate`混入的表达式使用，用于在类型检查和查询优化过程中识别聚合操作。

```mermaid
flowchart TD
Start["表达式类型检查"] --> CheckAggregate["调用 isAggregate()"]
CheckAggregate --> IsAggregate{"返回 true?"}
IsAggregate --> |Yes| HandleAggregate["作为聚合表达式处理"]
IsAggregate --> |No| HandleNonAggregate["作为普通表达式处理"]
HandleAggregate --> Optimize["查询优化"]
HandleNonAggregate --> Optimize
Optimize --> GeneratePlan["生成执行计划"]
GeneratePlan --> End["执行查询"]
```

**Diagram sources**
- [aggregate.ts](file://src/expressions/mixins/aggregate.ts#L21-L23)

### isNester() 方法
`isNester()`方法标识表达式是否具有嵌套作用域的特性。在Plywood中，聚合表达式通常会创建新的作用域层次，`isNester()`返回`true`表明该表达式会增加作用域嵌套深度，这对于变量解析和作用域管理至关重要。

### fullyDefined() 方法
`fullyDefined()`方法用于判断聚合表达式的完全定义状态。它检查操作数是否为字面量且表达式是否已解析，这对于表达式简化和优化决策非常重要。

```mermaid
flowchart TD
Start["检查完全定义状态"] --> CheckOperand["operand.isOp('literal')"]
CheckOperand --> IsLiteral{"是字面量?"}
IsLiteral --> |No| NotFullyDefined["未完全定义"]
IsLiteral --> |Yes| CheckExpression["expression.resolved()"]
CheckExpression --> IsResolved{"已解析?"}
IsResolved --> |No| NotFullyDefined
IsResolved --> |Yes| FullyDefined["完全定义"]
NotFullyDefined --> End
FullyDefined --> End
```

## 混入模式实现
Plywood使用TypeScript的混入模式来实现聚合功能的扩展。`Expression.applyMixins()`方法是混入机制的核心，它将混入类的方法复制到目标类的原型上。

```mermaid
sequenceDiagram
participant SumExpression as SumExpression
participant Expression as Expression
participant Aggregate as Aggregate
SumExpression->>Expression : applyMixins(SumExpression, [Aggregate])
Expression->>Expression : 遍历混入类
Expression->>Expression : 复制原型方法
Expression->>SumExpression : 将isAggregate()复制到原型
Expression->>SumExpression : 将isNester()复制到原型
Expression->>SumExpression : 将fullyDefined()复制到原型
Expression-->>SumExpression : 完成混入
```

## 查询优化与执行
### 表达式简化
聚合表达式通过`simplify()`方法进行优化，将复杂的表达式转换为更简单的等价形式。

```mermaid
flowchart TD
Start["原始表达式"] --> Simplify["调用 simplify()"]
Simplify --> CheckFullyDefined["检查 fullyDefined()"]
CheckFullyDefined --> IsFullyDefined{"完全定义?"}
IsFullyDefined --> |Yes| Evaluate["计算并返回字面量"]
IsFullyDefined --> |No| CheckPushExternal["检查是否可推入外部"]
CheckPushExternal --> CanPush{"可推入外部?"}
CanPush --> |Yes| PushExternal["推入外部并返回"]
CanPush --> |No| ReturnSimpler["返回简化后的表达式"]
Evaluate --> End
PushExternal --> End
ReturnSimpler --> End
```

## 总结
Plywood的聚合功能扩展体系通过混入模式实现了高度模块化和可扩展的架构设计。`Aggregate`混入类为所有聚合表达式提供了统一的接口和行为规范，而具体的聚合实现则专注于各自的计算逻辑。这种设计模式不仅提高了代码的可维护性，还为未来的功能扩展提供了便利。

该体系在表达式类型检查、查询优化和执行计划生成等方面发挥着关键作用，确保了聚合操作的正确性和高效性。通过与其他混入的协同工作，Plywood能够支持复杂的分析场景，满足多样化的数据分析需求。
